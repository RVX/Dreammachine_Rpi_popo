# RP2350B firmware and Raspberry Pi communication

The custom shield exposes two separate interfaces between the Raspberry Pi 4
and RP2350B:

| Purpose | Pi BCM GPIO | RP2350B signal |
| --- | --- | --- |
| SPI clock | 11 | GPIO18 / SPI0 SCK |
| SPI MOSI | 10 | GPIO20 / SPI0 RX |
| SPI MISO | 9 | GPIO19 / SPI0 TX |
| SPI chip select | 8 | GPIO17 / SPI0 CSn |
| SWD data | 23 | SWDIO |
| SWD clock | 24 | SWCLK |
| Reset | 22 | RUN |

SPI controls a firmware image that is already running. It does not rewrite
the RP2350B flash. Firmware updates use USB BOOTSEL or SWD.

The same one-byte runtime commands are accepted through the RP2350 USB serial
port. This permits standalone shield testing before a Raspberry Pi is fitted.
Send raw byte values, not their hexadecimal text representation.

## Pattern commands

| Byte | Command |
| ---: | --- |
| `0x00` | All MOSFET outputs off and amplifier shut down |
| `0x01`-`0x06` | Pulse AMOS1-AMOS6 for 500 ms |
| `0x10` | Four forward chase cycles |
| `0x11` | Three forward/backward bounce cycles |
| `0x12` | Flash all outputs five times |
| `0x20` | Mute, then place TPA3118 in shutdown |
| `0x21` | Start TPA3118 but keep it muted |
| `0x22` | Unmute only when `FAULTZ` is high |
| `0x23` | Mute TPA3118 |

From the Pi:

```sh
python3 rp2350/pattern.py chase
python3 rp2350/pattern.py bounce
python3 rp2350/pattern.py flash
python3 rp2350/pattern.py pulse 1
python3 rp2350/pattern.py off
```

For a shield powered only through RP2350 USB-C, send a command from a computer:

```sh
python3 - <<'PY'
import serial

with serial.Serial('/dev/ttyACM0', 115200, timeout=2) as port:
  port.write(bytes([0x11]))  # bounce
  port.flush()
PY
```

## Build

Build on a workstation with Pico SDK 2.2.0 or newer and an Arm GNU toolchain:

```sh
export PICO_SDK_PATH=/path/to/pico-sdk
export PICO_TOOLCHAIN_PATH=/path/to/arm-none-eabi/bin
cmake -S rp2350 -B rp2350/build -G Ninja \
  -DPICO_BOARD=weact_studio_rp2350b_core \
  -DPICO_COMPILER=pico_arm_cortex_m33_gcc
cmake --build rp2350/build
```

## Flash from the Raspberry Pi over SWD

Copy `dreammachine_rp2350.elf` to the Pi, then run from the repository root:

```sh
sudo openocd \
  -f rp2350/rpi4-rp2350-swd.cfg \
  -f target/rp2350.cfg \
  -c 'adapter speed 1000; program rp2350/dreammachine_rp2350.elf verify reset exit'
```

The board-specific OpenOCD file is required. The packaged
`raspberrypi-swd.cfg` uses different GPIOs and must not be used directly.
GPIO22 is physically connected to RUN, but OpenOCD's RP2350 target uses the
core `SYSRESETREQ` mechanism and therefore does not configure GPIO22 as SRST.

Expected successful output includes the RP2350 revision, W25Q128 flash ID,
`Programming Finished`, and `Verified OK`. On the reference unit the detected
flash was 16 MiB with JEDEC ID `0x1840ef`.

After flashing, verify runtime SPI communication:

```sh
python3 rp2350/pattern.py bounce
python3 rp2350/pattern.py off
```

The first command must produce a visible forward/backward sweep. The second
command is always sent after a test so all six MOSFET controls finish low.

Reference result (`sjcdm1`, 2026-09-16): SWD identification, W25Q128 program
and verify, SPI bounce pattern, and final all-off command all passed.
